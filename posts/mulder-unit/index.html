The M.U.L.D.E.R. Unit: DIY Portable Multi-Sensor

Nov 20, 2026 hardware raspberry-pi react

The Idea

It's a Multi-Use Live Display Emissions Receiver (M.U.L.D.E.R.) that can be deployed on the go, or in the comfort of your own home.

Seen a spook, specter, or ghost? Use the on-board cameras and sensors to scan thermal, infrared, sonic, and many more types of paranormal-adjacent spectra.

Second guessing what you saw? Attached air quality sensors can measure Carbon Monoxide (a common cause of hallucinations and paranoia) along with Ethanol (portable breathylizer).

Think you've been abducted or someone's implanted a tracker? Use the short range metal detector (ferrous and non-ferrous) to give yourself a subcutaneous sweep.

The Reality

  • ~$450 in hardware
  • ~2 months in time from research to completion

I spent about 2 weeks planning and researching parts before I purchased anything. I also diagrammed out what I thought the parts and connections would look like, a process I found to be a lot of fun even though I've never done any technical drawing before.

My research paid off with the sensor and Pi purchases, they were all compatible and correct when they arrived. The only flaw was a dead air quality sensor on the Environmental Sensor HAT, but I had a separate gas sensor on the way (the Carbon Monoxide was the big one I wanted) so I didn't bother to return it. Later, the EMF sensor on the same HAT failed, so that was unfortunate, but I elected to remove that sensor from the backend/frontend rather than deal with an overseas return and replacement.

Lots of cables and standoffs were ordered, and a family member was nice enough to 3D print me the mounting boards that everything is attached to, and gradually I was able to start connecting everything together. I wired the Pi to a display, connected a sensor, installed the necessary libraries, and tested a sensor reading with varying levels of success. After troubleshooting was complete, that sensor got its own API endpoint in the Flask backend (build with Claude), and a stubbed out page in the React frontend. Rinse and repeat for every sensor.

After every sensor was connected and reporting data correctly, and the endpoints were spitting it out in a legible format, I built the React frontend to be a kiosk chrome window containing what is essentially a tabbed interface. The display is a touch screen, and the Pi has bluetooth for connecting a mouse and keyboard, but there are wired hardware controls (a knob and two buttons) to navigate the interface.

The Post-Mortem

While the housing and mounting leaves a lot to be desired (it's my first build), the end result is very satisfying from a software perspective. I am primarily a web developer, and interacting with hardware was a fun challenge that taught me a lot in the process. If I had it to do over again, I think I would try to look for a camera that had day/night/thermal vision in one unit, instead of splitting it across 2 cameras and trying to align their output (it doesn't look great). Other than that I'm pretty happy with it, but I do intend to improve the housing and mounting.

Software

On-device backend (mulder-backend)

  • Python + Flask API serving each sensor at its own endpoint; each sensor initialises independently, so a missing one doesn't take the server down
  • Lightweight database storing historical sensor readings and screenshots
  • Adafruit Blinka / CircuitPython drivers for the BME280, TSL2591 and LTR390
  • smbus2 register-level drivers written for the LDC1612 and XM125, which have no Adafruit drivers
  • Seengreat MLX90642 C driver, compiled and loaded through Python's ctypes
  • rtl-sdr tools (rtl_sdr for IQ snapshots with a NumPy FFT, rtl_fm piped to aplay for live radio audio)
  • Server-Sent Events stream that turns Qwiic button and encoder input into UI intents

Interface (mulder-ui)

  • React 18 + Vite
  • Material UI v5 for components and icons
  • Plotly for every sensor chart, spectrogram, waterfall and heatmap
  • React Router v6 for mode navigation
  • Custom CSS theme sized for the 800×480 display

Operating system and deployment

  • Debian Trixie with the labwc Wayland compositor
  • Chromium in kiosk mode, fullscreen on boot
  • systemd services for the backend and UI, started automatically at power-on
